component placement notes
01
input layer
Educator CLI
Runs on the educator's own laptop or workstation. Built with prompt_toolkit. Communicates with the orchestrator over WPI LAN (or VPN). No data stored locally — session state lives on the agent host.
02
agent core
Orchestrator host
A single on-prem Linux server. All Python tools are installed here: canvas-mcp, python-gitlab, GitPython, Paramiko, SQLite. This is the only machine that talks to ARC, Canvas, GitLab, and lab servers.
03
LLM inference
WPI ARC cluster
The orchestrator calls arc-ai-rag-01.wpi.edu over WPI LAN via HTTP POST. No data leaves WPI network. ARC manages GPU nodes and load balancing. Start with Llama 3.1 70B — consult ARC team for model hosting.
04
canvas MCP
canvas-mcp server
Installed and runs on the agent host as a local MCP server process. The orchestrator calls it via stdio or local socket. It translates tool calls into Canvas REST API calls over HTTPS to wpi.instructure.com.
05
gitlab
Source of truth
WPI's on-prem GitLab instance. One repo per institution or per course. The GitLab tool on the agent host clones locally and pushes via HTTPS or SSH. Git history is the complete change log — no separate versioning needed.
06
lab servers
SSH via Paramiko
Lab servers are reachable over WPI internal network only. The Lab Runner tool on the agent host uses Paramiko with key-based auth to SSH in, execute readiness check commands, and capture stdout/stderr as structured pass/fail results.
